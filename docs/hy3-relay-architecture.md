# Hy3 Relay 架构与数据边界

## 目标

Hy3 Relay 解决多种 AI 编程工具之间的上下文断裂：把已有代码、日志、diff 和任务说明整理为
带证据的交接包，让目标工具从已确认进度继续，而不是从头猜测。

## 数据流

```text
本地输入
  → 文件类型/大小校验
  → 确定性脱敏
  → 用户查看实际发送预览
  → Hy3 高推理结构化整理
  → Zod 结构校验
  → 原文证据核验
  → 目标工具适配
  → Markdown / JSON 导出
```

## Hy3 负责什么

- 理解多份代码、日志和任务说明；
- 区分已完成内容、事实、决策、风险和未知项；
- 生成严格的结构化交接内容；
- 给出带验证方法的下一步。

## 本地程序负责什么

- 白名单文件类型和单文件 120 KB 上限；
- 最多 8 份材料；
- API Key、Bearer Token、GitHub Token、云密钥、secret 赋值和本机用户目录脱敏；
- 发送前预览与 SHA-256；
- 输出结构校验和证据引用核验；
- 六种目标工具的确定性提示词适配；
- 明确的 401、429、超时、网络、空内容、非法 JSON 和非法结构错误；
- 真实模式失败时不静默切换离线样例。

## 隐私边界

- 服务只绑定 `127.0.0.1`；
- 不使用数据库；
- 输入和结果只在当前进程内存中处理；
- API Key 使用 Windows DPAPI 加密保存，启动时仅解密到子进程环境；
- 日志、工具安装、验证副本、密钥文件和构建产物都不进入提交；
- 离线样例由用户显式选择，页面持续显示离线标识。
